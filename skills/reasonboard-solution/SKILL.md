# ReasonBoard — solution

Answer the **gap**, don’t dump features.

## Typical section set (adapt names)

1. Idea / framing (optional `pairs` problem→solution per persona)
2. Proactive / inbox
3. Improve (propose → approve → apply)
4. Guides / cases
5. Brain / memory
6. Roadmap (phases) + parked `ideas[]`

## Roadmap shape

Three phases with timeboxes (example):

| Phase | Time | Ships |
|-------|------|--------|
| 1 | 1–2 mo | Inbox + advice GenUI + first guides |
| 2 | 3–4 mo | Apply after approve + memory + measure after |
| 3 | 5–6 mo+ | Whitelist autonomy + personality |

## Rules

- Every muscle must map to a persona pain or competitive gap.
- Side ideas go in `ideas[]` — they must not dilute the core thesis.
- User-facing copy: plain language (“only after you approve”), not tool jargon.
- Keep **4–7** root cards on the solution slide.
